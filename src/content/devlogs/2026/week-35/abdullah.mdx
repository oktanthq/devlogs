M2 is about the machinery that gives Oktant meaning, and for me that started with the parser. The pipeline description language was getting its first real implementation.

### Not regex

The previous prototype treated describe-files as text to be scraped. That dies this week. The core now has a genuine parser: a lexer producing tokens, a recursive-descent parser producing an AST, and — the part I care about most — an error model built around positions.

### Errors you can act on

A parser is only as good as its failures. Every parse error now carries a position, the offending snippet, and a human sentence about what the parser expected. The goal is that a first-time user never opens the docs to fix a syntax error, because the error itself is the documentation.

### The AST as the contract

The AST is the boundary between the core and everything downstream. It is typed, lossless with respect to the source (comments and structure survive), and explicitly versioned. When the IR work lands, the AST will be its input — and the parser will not care what happens after it.

Core work has a different texture than foundation work. Everything here either runs or breaks, and this week it started running.
