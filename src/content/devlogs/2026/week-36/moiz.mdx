The execution engine needs a floor before the pipeline can stand on anything. This week I build the primitives that everything else will assume exist.

### Run context

Every execution now travels with a context object: identity, working directory, environment, capability set, and an output sink. It is passed explicitly, never stashed in globals. The pipeline already depends on this contract, and Harris and I agree it is the right seam between planning and execution.

### Process primitives

The engine gained first-class process arrival and exit handling. A step is now a value: constructed, launched, awaited, reaped. Leaked children and orphaned handlers are the classic sources of undeclared runtime behavior, so the API is shaped to make forgetting impossible — you cannot launch a process without also declaring what happens when it exits.

### Determinism by default

Environments are built from the plan, not inherited. Time and locale are pinned unless a step explicitly opts out. Infra work like this is invisible when it works, which is the entire point — the foundations should cost the pipeline nothing to reason about.

Next week the supervision layer goes in, and the engine gets its first real teeth.
