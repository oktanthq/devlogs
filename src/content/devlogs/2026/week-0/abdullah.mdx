## Starting incrementally

We decided to build the Oktant frontend incrementally instead of trying to design and implement the entire product surface at once. Each phase should give us a usable foundation,
make the next decision easier, and leave behind something we can evaluate as a team.

For the application frontend, we are going to use **Next.js** and **React**. That gives us a familiar component model and a practical path from the first interface to a
larger product without forcing every early decision up front.

## A separate home for the work

We also decided that the development work should be documented in public at [dev.oktant.tech](https://dev.oktant.tech). The site is intentionally separate from the main product
frontend: it is a place to explain what we are building, why we are making certain choices, and what we learn along the way.

The devlog site itself is a static site built with **Astro**. Static output keeps the site simple, fast, and easy to deploy. It also fits the content well.

## Weekly devlogs

At minimum, we want to publish a devlog every week. The goal is not to manufacture progress or write a perfect report. It is to keep a reliable record of the decisions,
experiments, and unfinished work that shape Oktant over time.

## Phase 1

Phase 1 is intentionally modest: this under-development site is the first version of that foundation. It gives us the publishing surface, the basic visual language, and a place to start building the habit of writing weekly.

There is still plenty to improve, but the direction is now clear: build the product in increments, document the process openly, and let each phase inform the next one.
